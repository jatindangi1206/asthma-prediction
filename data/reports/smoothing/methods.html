How the 10 smoothing methods work

Plain-language guide: what each method does, which settings it has, and which values we derived from the data. Open the dashboard to see them on real patients.

The idea

  • The watch gives one HRV value about every 10 minutes. Each value = the patient's true current HRV level + random noise (movement, a bad measurement window). A smoother tries to recover the true level.
  • Too little smoothing leaves the noise in. Too much erases real changes — including the ones that may signal an attack. The goal is the balance that fits this data.
  • Every method only looks at past and current readings, so it could run live on the watch. A gap of 3 h or more splits the recording into segments; each method starts fresh in each segment. Segments with fewer than 10 readings are left unsmoothed.

How the settings were chosen

Nothing was tuned or searched. We measured a few properties of each patient's HRV, took the median across the patients of a cohort, and converted them into each method's own settings. This was done separately for AIIMS, COPD and both together.

Settings that cannot be measured from the data keep their standard values; each card lists them. Default = the value the code shipped with. Highlighted values differ from the default.

At a glance

Closeness to ideal: how far the method's behaviour (noise removed, peaks kept, similarity to the raw signal) is from the best possible live filter for data like ours, simulated with the measured noise and memory. 0 = identical; lower is better. AIIMS + COPD patients.
Live-safe: "yes" = a value never changes when later readings arrive. "almost" = filters forward, but scales a few numbers (e.g. the patient's noise level) using the whole recording, so it peeks slightly ahead.
